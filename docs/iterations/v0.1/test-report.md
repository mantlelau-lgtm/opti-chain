# v0.1 测试报告

## 测试范围

采购收货闭环、销售锁库闭环、准入/信用管控、表头编辑、MRP 在途语义。方式为 API 级端到端脚本断言（信封码 + 数据状态），辅以无头 Chrome 控制台检查与真实浏览器截图。

## 测试环境

macOS (M5 Max) / Go 1.26 / SQLite / Chrome headless；后端 :8088、前端 :5173。

## 测试结果

| 类别 | 总数 | 通过 | 失败 | 跳过 |
|------|------|------|------|------|
| 收货闭环 | 19 | 19 | 0 | 0 |
| 销售闭环 | 18 | 17* | 1 | 0 |
| 超卖守卫补测 | 2 | 2 | 0 | 0 |
| 表头编辑 | 3 | 3 | 0 | 0 |
| 前端渲染 | 2 | 2 | 0 | 0 |

\* 该「失败」为测试数据设计问题（金额先触发信用拦截），非代码缺陷；已用低单价用例补测确认库存守卫独立生效。

## 关键断言示例

- 草稿单收货被拒；拒收无原因被拒；超收被拒（`received_qty + ? <= order_qty`）
- 合格 6+5 后：库存 = 11（拒收 2 未入）、PO = IN_PROGRESS、received 只记合格
- 收满自动 COMPLETED；收货单号按 PO 序号不冲突
- 审批锁库：locked 6 → 可用 4；超量审批 40000；信用超限 40900
- 取消释放 locked 与 used_credit；释放后可再审批
- 未核准供应商下 PO 被拒；核准后通过；已驳回客户建 SO 被拒
- 表头编辑：code=0 且明细/状态/收货进度不变
- 无头 Chrome 控制台零 Uncaught 错误；真实页面渲染完整

## 缺陷列表（本轮发现并修复）

| # | 缺陷 | 修复 |
|---|------|------|
| 1 | GORM 级联双插致建单主键冲突 500 | `Omit(clause.Associations)` |
| 2 | SQLite 亲和性致锁库守卫恒假 | 谓词列在左侧 |
| 3 | 需求日期只收 RFC3339 | handler 字符串 + parseTime |
| 4 | PO 编辑误走全量更新 | UpdateHeader 分流 |
| 5 | 前端 Form.List 缺闭合、MaterialPage 缺导入 | 补标签/导入 |
| 6 | vite 仅 IPv6 回环 | `host: true` |

## 结论

v0.1 闭环功能全部验证通过，可交付试用。单元测试缺口列入行动项。
