# v0.1 复盘记录

## 做得好的

- **闭环优先**：每个机制（收货、锁库、信用、准入）都带负例的端到端验证，缺陷在交付前暴露。
- **语义设计正确**：`received_qty 只累计合格量` 让 MRP 在途自动包含拒收待补，零补偿逻辑。
- **模式沉淀**：`*InTx` 事务参与、守卫 UPDATE、信封映射形成固定套路，新模块（销售）一天内接入。
- 文档与代码同迭代交付，接口/数据模型/架构齐备。

## 待改进的

- **零单元测试**：全靠 E2E 脚本，回归成本高；守卫 SQL 这类纯逻辑应下沉为表驱动测试。
- **前端复制粘贴债**：Form.List 缺闭合在两个页面同源出现，说明页面靠拷贝生成、缺乏构建期校验（CI 跑 `npm run build` 可立即发现）。
- **种子数据缺失**：空库试用体验差，应提供 `seed` 命令或脚本。
- **状态机无方向校验**：PO/SO 状态靠调用方自觉，SetStatus 应校验合法迁移。
- 库存单据删除不回冲，靠 FAQ 口头约定，长期应做反向单据或禁止删除已执行单。

1. v0.2 引入批次管理（inv_batch + 库存批次维度）与发货执行（shipped_qty 推进、出库释放锁定）。
